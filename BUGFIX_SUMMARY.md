# Bugfix Summary: Regenerate Basmati Rice Blockchain Hashes

## Ticket Information
**Branch:** `bugfix-regenerate-basmati-rice-blockchain-hashes`
**Issue:** Basmati Rice blockchain showing 4/4 invalid blocks while Groundnut Oil showing 0 invalid blocks

## Problem Description
The blockchain verification system was correctly validating Groundnut Oil events (0 invalid blocks) but incorrectly showing all Basmati Rice events as invalid (4/4 blocks). This indicated that:
1. The hash calculation logic in `calculateEventHash()` was working correctly
2. The Basmati Rice blockchain events had old/incorrect hashes that didn't match the verification logic

## Root Cause Analysis
The original `regenerate-blockchain-hashes.mjs` script used **placeholder/simplified data** for Basmati Rice that didn't match the actual event data in `traceabilityData.ts`:

### Mismatches Found:
1. **Actor name:** Script used `'Suresh Gupta (Farmer)'`, actual data had `'Harpreet Singh (Farmer)'`
2. **Location structure:** Script used string format, actual data used complex object with coordinates and GLN
3. **Event data:** Complete mismatch in all data fields

This meant the hashes generated by the script were calculated from different data than what was actually stored in the file, causing all verification checks to fail.

## Solution Implemented

### 1. Created New Regeneration Script
**File:** `scripts/regenerate-basmati-hashes.mjs`
- Uses the ACTUAL event data from `traceabilityData.ts`
- Follows the same hash calculation pattern as Groundnut Oil
- Generates correct SHA-256 hashes using `calculateEventHash()`

### 2. Updated Blockchain Event Hashes
**File:** `src/data/traceabilityData.ts`

Updated all 4 Basmati Rice events with correct hashes:

| Event | Type | Old Hash | New Hash |
|-------|------|----------|----------|
| evt-11 (Block 0) | planting | `3cca3c4167be...` | `0c33c37aeff2...` |

| evt-14 (Block 3) | pest-treatment | `97c8c2330258...` | `afd6575a48f0...` |

### 3. Created Verification Test Script
**File:** `scripts/test-basmati-verification.mjs`
- Validates all Basmati Rice event hashes
- Checks chain linkage (previousHash matches prior event's currentHash)
- Confirms 0 invalid blocks

### 4. Fixed TypeScript Linting Issues
**File:** `src/utils/blockchain.ts`
- Changed `any` type to `unknown` in `canonicalJSON()`
- Changed `any` to `Record<string, unknown>` in `calculateEventHash()`
- All linting and type-checking now passes

## Key Learnings

1. **Use Actual Data:** Always regenerate hashes using the exact data structure from the source file, not placeholder data
2. **Verify Each Product:** Test each product's blockchain separately to catch product-specific issues
3. **Match Verification Logic:** Hash generation must use the same logic and data structure as verification
4. **Maintain Type Safety:** Use proper TypeScript types instead of `any` to catch issues early

## Future Maintenance

When adding or modifying blockchain events:

1. **Use `calculateEventHash()`** from `src/utils/blockchain.ts`
2. **Match data structure** exactly between event data and hash calculation
3. **Link chain properly:** Each event's `previousHash` = prior event's `currentHash`
4. **Test immediately:** Run product-specific verification scripts
5. **Never use placeholder data** when regenerating hashes
